Design Pass v2 · 01

Critique — current UI vs. the calibrated-instrument bar

Judged against Linear’s density and precision, Stripe/Mercury’s layered trust, Robinhood’s restraint. The v1 handoff fixed structure (hierarchy, nesting, selection, steppers) and the code adopted it faithfully — none of that is relitigated. What remains is craft: color discipline, contrast order, numeric treatment, and chrome density. Findings are ranked; every one cites the file that changes and links to its fix.

01Ranked findings

R1high

Color has no discipline — the accent is decoration, categories wear state colors

Evidence: two decorative accent gradients frame every screen (AppShell.module.css · .topbar::before, styles.css · .run-log-panel::before) — explicitly “gradients-for-decoration.” Every workflow card carries a filled blue badge (styles.css · .choice-card__badge shares .status-chip--info), so four blue pills sit at the top of the page before the user has done anything. Inspected column names — plain category data — render as up to 8 blue chips (FmeaTool.tsx · analysis-summary__chips). Two filled chips (green + blue) burn in the topbar permanently (App.tsx · statusRow). Log INFO tokens are accent-colored (styles.css · .run-log-panel__level--info), so a healthy log is speckled blue.

Fix: gray builds structure; color appears only as a 6px dot, a text token, or a count badge, and only for state. Backend health becomes a dot + text in the log strip; column chips become mono text; gradients deleted; INFO goes neutral. See both states of the mockup and N2/N3/N10.

R2high

The primary action is hidden behind a tab

Evidence: “Generate FMEA” lives inside the side panel’s Run tab (FmeaTool.tsx · contextView + ContextTabs, RunStatePanel.tsx). In the default Preview tab the tool has no visible way to run. Readiness is discoverable only by clicking Generate and reading a rejection toast. For the emotional job — “I am about to stake a safety analysis on this” — the app hides both the trigger and the preflight state.

Fix: a persistent Run rail: readiness checklist (inputs · required mapping · output) with live mono values, the CTA always visible, blocked-reason text under it, progress/phases/result in the same card. Tabs retire. Mockup states Pristine → Success; N5.

R3high

The text hierarchy is literally inverted, and every label shouts

Evidence: --text-faint: #5e6d81 is darker than --text-muted: #617289 (styles.css · :root) — the WCAG bump flipped the fourth tier above the third, so “faint” metadata outweighs hints. On top of that, ~10 different roles all render as 11px semibold UPPERCASE with 0.08em tracking (eyebrows, table headers, metric labels, chip text, panel titles, filter options…), so structural labels visually outrank the data they describe.

Fix: monotonic 4-tier ramp (≈16.6 / 9.3 / 5.9 / 4.6:1 — Tokens 03); uppercase demoted to two roles (nav group labels, log level tokens); labels drop to weight 500 sentence case. N1.

R4high

Half the numbers aren’t on the instrument standard

Evidence: paths and logs are mono, but the values engineers actually read are proportional Inter: the hero metric % (styles.css · .hero-metric — tabular-nums on a proportional face does nothing useful), run-result Primary/Secondary metrics (RunStatePanel.tsx · .run-result__metric), header metrics (FmeaTool.tsx · .header-metric), run ID, progress %, ETA, validation counts. The guardrail is explicit: mono + tabular-nums for all numbers, IDs, RefDes, timestamps.

Fix: one .num utility (tokens-v2.css) applied at every numeric call site; Excel headers and sheet names are identifiers → mono too. Specimen: Data Surface 03; call-site list in N4.

R5med

Density is inverted: chrome is generous, data pays for it

Evidence: the topbar stack (eyebrow + 28px title + subtitle paragraph + two chips) spends ≈100px on constants (AppShell.module.css · .topbar/.title/.subtitle). Controls are 36px, the CTA 44px (styles.css · .run-state__controls .primary-button), every section repeats an always-visible description paragraph (FmeaTool.tsx · SectionCard descriptions), and each workflow card carries body copy. Meanwhile the mapping table — the actual work — needs a scroll. Linear’s equivalent chrome is a 40–48px bar.

Fix: 48px topbar (14px title + mode inline), 28px controls / 32px CTA / 24px table controls, section descriptions removed or demoted to tooltips, workflow summaries to one 11px line. The mockup’s full run screen fits 1440×900 with no scroll. N2/N5/N9.

R6med

Surface roles are ambiguous; states are communicated by dimming

Evidence: --surface-muted #f8fafc, --surface-soft #f2f5f9, and --section-surface-decoration alternate with no rule (analysis panels, input-card states, column pickers, table headers each pick differently). Pending input cards drop to opacity: 0.62 (styles.css · .input-card[data-state="pending"]) — text goes sub-AA and fuzzy. The borders-only pledge is broken by --shadow-rail-active’s glow (AppShell.module.css · .toolButton[data-selected]).

Fix: two grays with names — muted = hover, soft = sunken well (Tokens 02); step state moves into a 14px leading indicator (ring → dot → check) with text at full contrast; rail glow → none. N1/N6.

R7med

Pill language: consumer-rounded, and still color-coding categories

Evidence: 999px filled pills at 22px min-height carry everything from LOADED to FMD-2016 (styles.css · .status-chip/.badge-state). v1’s own vocabulary says categories are neutral, yet .choice-card__badge hard-inherits the filled accent treatment, and mapping statuses render as four colored pills per screenful of rows. Fully-rounded tinted pills read Robinhood-consumer, not instrument.

Fix: 18px / 4px-radius rectangles for the few true badges (severity counts, “capped”); dot + word for row states; plain text for categories. Data Surface 02-⑤, N10.

R8med

File inputs: five ~130px cards for one decision each

Evidence: each input renders label row + path row + helper paragraph + sheet select + Browse + up to two status notes (InputGrid.tsx, styles.css · .input-card) — the FMEA inputs section alone is ≈500px. Helper copy (“Sheets loaded from the desktop backend bridge.”) restates the chip above it.

Fix: a grouped list of 44px rows — indicator · role · path (mono, middle-truncated, hover copy) · sheet · Browse. Helpers become tooltips; errors are the only row that grows. Mockup step 02; N6.

R9med

The mapping table reads as a form, not a data surface

Evidence: ~44px rows (10px cell padding + 32px select), a colored pill per row, and a Recommendation column of full sentences that repeats “Exact header found in …” twelve times (MappingTable.tsx). Source columns — workbook identifiers — render in Inter inside heavy bordered selects.

Fix: 32px rows, quiet selects (border on hover), mono source values, dot status, notes at 11px faint with inline Apply match on hover, toolbar counts + coverage meter as telemetry. Full spec: Data Surface v2; N7.

R10low

Selection floods: three cues where one would do

Evidence: [data-selected="true"] applies accent border + accent-soft wash + accent eyebrow simultaneously (styles.css · unified selection rule). On a 170px workflow card the tint field dominates the page and reads as an alert, not a choice.

Fix: keep the single rule, soften its output: 1px --accent-border + 4% tint + a small check glyph; text stays neutral. Segmented value-pickers select neutrally (raised segment). N9.

R11low

The focus ring is invisible

Evidence: --shadow-focus-ring: 0 0 0 3px rgba(35,94,231,0.08) — 8% alpha (styles.css · :root). For a keyboard-driven audience, tab position is effectively unmarked on light surfaces.

Fix: 2px ring at 35% (light) / 45% (dark) + accent border on the focused control. Token-only change. N1.

R12low

Micro-inconsistency inventory

Status dots at 6, 8, and 10px (styles.css · .global-log-panel__filter-count-dot / .settings__health-dot / .run-log-panel__status-dot); letter-spacing at 0.02 / 0.03 / 0.04 / 0.08em across chip variants; a one-off 3px radius on log-line hover; the log grid reserving a fixed 160px for a tool tag that is ≤6 characters; chip heights 22px vs control 36px vs CTA 44px with no shared rhythm.

Fix: normalize on tokens: dots 6px, badges 18px, controls 28/32, tracking from the two tracking tokens, radii from the 4/6/8 scale. Sweep list in N10.

02What already clears the bar — don’t touch

  • The 11/13px dense type core and self-hosted Inter/JetBrains Mono. Correct and deliberate.
  • Architecture: theme registry, tool registry, keep-alive shell, escape-layer stack, command palette, per-tool error boundaries.
  • A11y instrumentation: reduced-motion overrides, aria-live run meta, focus management on tool switch — v2 layouts must preserve all of it.
  • Comment discipline in CSS — rationale-per-deviation is rare and valuable; keep the habit through v2.
  • v1 structural wins: single title source, Review drawer, SectionCard variants, unified selection attribute, hold-to-cancel.
