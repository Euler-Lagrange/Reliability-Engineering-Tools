02Anatomy

1Row height 32px (--row-h) — down from ~44px (10px cell padding + 36px select). 12 fields fit in 384px instead of ~530px; the whole table sits in one glance.
2Header row is sentence-case, 11px/500 --text-muted. Uppercase tracking is retired from table headers — it was competing with the data. Headers describe; data performs.
3Field column stays UI type: 12px/500 --text, sans. Canonical fields are the app’s vocabulary, not workbook data. Required marker is a plain * with a title tooltip — no amber pill.
4Source column is workbook data → mono. Quiet select: transparent until hover, then a 1px --line-strong border. Value renders in JetBrains Mono 11px — Excel headers are identifiers and should look like them. Empty value falls back to sans --text-faint “— Not mapped —”.
5Status is a 6px dot + word, not a filled pill. Auto=success, Manual=accent, Unmapped=warning (required only), Derived=hollow. One colored pixel-cluster per row instead of a 60px colored bar — 12 rows stop looking like an alarm panel while the scan pattern (color column) survives.
6Note column whispers: 11px --text-faint, single line, ellipsis, full text on hover. The inline Apply match action appears on row hover — visible affordance on the only rows that need action.
7Toolbar counts are the table’s telemetry: 8 auto · 2 manual · 1 derived · 1 unmapped with numerals in mono/tnum. The old amber “N unmapped” pill becomes just another count — the coverage meter in the section header (72×3px bar + 10 / 11) carries the at-a-glance signal.
8Hover = --surface-muted full-row tint, 150ms. No zebra striping; hairlines --line separate rows.

03Numeric treatment — why mono + tabular-nums is a rule, not a taste

Failure-rate ratios, row counts and RefDes columns are compared vertically. Proportional Inter shifts digit widths per glyph, so magnitude is unreadable at a glance and columns shimmer when values update. The rule (tokens-v2.css · .num): every number, ID, RefDes, path, timestamp, and Excel header renders var(--font-mono) + tabular-nums.
